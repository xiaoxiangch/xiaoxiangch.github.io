Steel Plate Fault Classification

Part 1 — Exploratory Data Analysis  ·  Part 2 — Multiclass Modelling

Overview

A dataset of steel plates' faults, provided by Semeion, Research Center of Sciences of Communication, classified into seven different types. The goal it was built for is automatic pattern recognition — training a model to assign the fault type from production attributes alone.

The Data

The Semeion / UCI Steel Plates Faults set: 1,941 rows × 34 columns — one row per detected defect, 27 predictors and seven one-hot target columns. No missing values anywhere.

The 27 predictors fall into four groups:

Group # Columns
Position 4 X_Minimum, X_Maximum, Y_Minimum, Y_Maximum
Size & shape 15 Pixels_Areas, X_Perimeter, Y_Perimeter, LogOfAreas, Log_X_Index, Log_Y_Index, SigmoidOfAreas, Square_Index, Empty_Index, Edges_Index, Edges_X_Index, Edges_Y_Index, Outside_X_Index, Outside_Global_Index, Orientation_Index

Target 7 Pastry, Z_Scratch, K_Scatch, Stains, Dirtiness, Bumps, Other_Faults

1 · Univariate Analysis

One column at a time — the 24 continuous columns as distribution plus boxplot with the skew printed on each panel, the three low-cardinality ones as bar charts.

  • Four features are extremely right-skewed. Y_Perimeter 39.3, X_Perimeter 21.5, Pixels_Areas 14.1, Sum_of_Luminosity 7.7 — each with 180–400 IQR outliers, roughly 10–20% of all rows.
  • Those outliers are signal, not error. A defect covering 152,655 pixels is a real extreme, not a mis-measurement, so nothing was clipped or dropped. We need to do log transformation to the linear models, while trees are invariant to monotone transforms.
  • Scales differ by seven orders of magnitude — Orientation_Index lives in [−0.99, 0.99] while Sum_of_Luminosity reaches 1.16×107. Anything distance-based has to be standardised first.
  • TypeOfSteel_A300 and TypeOfSteel_A400 are mirror images — 40% / 60% of the rows, and one is always 1 minus the other, so A400 was dropped as pure redundancy. Outside_Global_Index takes only three values (0, 0.5, 1) — a flag, not a measurement.

2 · Bivariate Analysis

Each feature against the fault label — the continuous ones as per-class densities and boxplots, the categorical ones first as raw counts, then as lift against each class's own prevalence.

Numerical Analysis
  • K_Scatch and Stains separate cleanly, in opposite directions — K_Scatch sits at the top of LogOfAreas and Pixels_Areas, Stains at the bottom, and their densities barely overlap the other five classes on either.
  • Pastry, Bumps and Other_Faults sit on top of each other on essentially every feature. This overlap, visible here in Part 1, is exactly the ceiling Part 2 runs into.
  • Steel_Plate_Thickness is banded, not continuous — most records sit at 40 or 70–80. It is a process parameter rather than a defect measurement, but the fault types are spread differently across those bands, so it still carries class information.

  • Six pairs exceed |r| = 0.9, and they are all the same two clusters: the bounding box (Y_Minimum / Y_Maximum at 1.000, X_Minimum / X_Maximum at 0.988) and the size cluster, where area, perimeter and total luminosity all measure how big the defect is.
  • The duplicates were kept. Collinearity destabilises linear coefficients but does not hurt a tree ensemble's predictions — it only splits their importance across the duplicated columns. So the fix was the log transform plus standardisation for the linear model, not feature deletion; the only column dropped was TypeOfSteel_A400, an exact complement of A300.
  • K_Scatch and Stains are opposite extremes on size — largest (Log_X_Index +1.5) versus smallest and brightest (LogOfAreas −1.6, Luminosity_Index +0.79).
  • Dirtiness is a shape signature — Square_Index −1.3, Orientation_Index +1.0, with size and luminosity mild.
  • Bumps and Other_Faults are flat across the entire row — no z-score reaches 0.6. Other_Faults has no fingerprint because it is not one defect, but the label for everything that is not the other six.

 Part 1 Key Takeaways

Which classes the features can actually tell apart:

  • Four classes are close to solved before any model runs. K_Scatch, Stains and Dirtiness each have a distinct signature in the z-score heatmap; Z_Scratch has none, and is separated by the steel type instead.
  • Three classes overlap almost completely. Pastry, Bumps and Other_Faults sit in the same range on nearly every feature.
  • The 12:1 imbalance decides the metric — macro-F1, which weights the 55-row class equally with the 673-row one.
  • Structural redundancy, cleaned once. A400 = 1 − A300 exactly.
  • Skew is data, not noise. The four features with skew 7.7–39.3 keep their outliers.

Part 2 — Multiclass Modelling

From "what the classes look like" to "which type is this fault"

Model Pipeline

Part 1 asked what each of the seven fault types looks like. Part 2 asks a model to do the classification.

  1. Split first, resample second. A stratified 80/20 split into 1,552 train / 389 test before anything else — SMOTE applied earlier would leak synthetic copies of test points into training.
  2. Log, then scale, then SMOTE — linear model only. log1p on the four heavy-tailed columns (skew 8.9–36.1 → 0.72–0.88), then StandardScaler, then SMOTE, inside the CV pipeline. The trees take the raw columns: monotone transforms and scaling change nothing for them.
  3. Class weights handle the imbalance. class_weight='balanced' for LR, RF and LightGBM; XGBoost has no such parameter, so a per-fold compute_sample_weight does the same job.
  4. Hyperparameter optimization. Grid search, randomised search and an Optuna study — all on the same 5-fold CV, each result compared to its own baseline fold by fold.

  • The three tree ensembles are within 0.01 of each other — XGBoost's −0.0037 is inside two standard errors, a tie. Only the linear model is out of the race, 0.12 macro-F1 behind.
  • Every tree model overfits by roughly 0.18 macro-F1 (train ≈ 1.00, CV ≈ 0.82), and no amount of regularisation closed it — 1,552 rows over 26 features is not enough data for the boundary between the overlapping classes.

What the Model Leans On

Two views of the same model: what it uses overall, and what it uses per class.

  • Other_Faults is the flattest column in the map — its largest reliance on any feature is 0.34, against 1.51 for K_Scatch and 1.26 for Z_Scratch. The model has nothing concentrated to hold on to.
  • SHAP confirms Part 1 independently. Z_Scratch leans on TypeOfSteel_A300 (0.77), Pastry on Orientation_Index (0.94), Dirtiness on Square_Index (0.48) — the same three signatures the EDA found.
  • Split count measures opportunity, not importance. Y_Minimum tops the bar chart, but it takes 1,939 distinct values across 1,941 rows — nearly a row index, so it offers the most places to split; SHAP puts it mid-table. Binaries are buried the other way: TypeOfSteel_A300 ranks near the bottom, yet SHAP shows it is Z_Scratch's single most important feature.

 Part 2 Conclusion

  • Final model: LightGBM. CV macro-F1 0.8202 ± 0.0085, test macro-F1 0.8267. XGBoost ties it statistically, Random Forest trails by 0.01, the linear model by 0.12.
  • Deployable today for four of the seven types. K_Scatch 0.955, Z_Scratch 0.935, Stains 0.931, Dirtiness 0.847 — together 36% of all records.
  • The other three need labels, not tuning. Pastry 0.640, Bumps 0.694 and Other_Faults 0.736 produce roughly three quarters of every error, and SHAP shows the model has nothing concentrated to separate them with.
  • Highest-value next step: split Other_Faults. Re-labelling the 673-record residual bucket into real defect types would lift the macro score further than any modelling change available here.
